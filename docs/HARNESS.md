# The render-test harness: flags and fixtures

GENERATED by `scripts/generate-tables.mjs` from `fixtures/render-test/src/harness/flags.ts` (the flag registry) and `fixtures/render-test/src/fixtures/catalog.ts` (the fixture catalog) — do not edit; run `pnpm docs.tables`.

THE URL IS THE FIXTURE. Every option of the harness (`fixtures/render-test`, `pnpm --filter plurid-render-test dev`) is a query flag; the SETUP button at the top-left expands into all of them — the layout switches on the live instance, the plane set / sizes / persistence re-create the application, everything else reloads the page — and rewrites the URL, so any state is shareable by pasting a link. A named FIXTURE is a set of flags (`?fixture=<name>`; its flags apply UNDER any explicit param, so a scenario can open a fixture and override one flag), optional link clicks, and the viewpoints the visual baselines are taken at. `?gallery=1` renders every fixture on one page (each in its own harness).

## Flags

`Applies` — `live`: the configuration prop of the mounted application; `remount`: a new application (no page load); `reload`: a page load (a startup-only option).
